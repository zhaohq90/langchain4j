## 📚 示例类详解

### 1️⃣ **MemoryExample.java** - 基础内存记忆示例

**功能说明**:
- 展示最基础的内存记忆使用方式
- 使用 `MessageWindowChatMemory` 保留最近 10 条消息
- 数据存储在内存中，程序重启后丢失

**核心代码**:
```java
// 初始化聊天记忆 (内存存储)
ChatMemory chatMemory = MessageWindowChatMemory.withMaxMessages(10);

Assistant assistant = AiServices.builder(Assistant.class)
    .chatModel(chatModel)
    .chatMemory(chatMemory)
    .build();
```

**适用场景**: 
- 临时对话
- 不需要持久化的场景
- 快速原型开发

### 2️⃣ **FileChatMemoryStore.java** - 文件持久化存储实现

**功能说明**:
- 实现 `ChatMemoryStore` 接口
- 将聊天记录持久化到本地文本文件
- 支持从文件加载历史聊天记录

**文件格式**:
```
memoryId|messageIndex|jsonContent
```

**核心方法**:
- `loadFromFile()`: 从文件加载所有聊天记录到内存缓存
- `saveToFile()`: 将当前缓存保存到文件
- `flush()`: 手动触发保存

**特点**:
- 每次 `updateMessages` 操作都会自动保存
- 支持多会话（不同 memoryId）
- 自动创建父目录

**适用场景**:
- 需要长期保存对话历史
- 本地应用、桌面应用
- 小到中等规模数据

### 4️⃣ **PersistentFileMemoryExample.java** - 文件持久化示例

**功能说明**:
- 演示如何使用 `FileChatMemoryStore` 实现聊天记录的持久化
- 聊天记录保存到 `./chat-memory.txt`
- 程序重启后可恢复之前的对话

**核心代码**:
```java
// 创建文件存储
FileChatMemoryStore fileStore = new FileChatMemoryStore("./chat-memory.txt");

// 使用文件存储的聊天记忆
ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .id("user-001")
    .maxMessages(10)
    .chatMemoryStore(fileStore)
    .build();
```

**运行效果**:
- 第一次运行：进行对话并保存记录
- 重新运行：读取之前的对话历史，AI 能记住之前说过的话

**适用场景**:
- 个人助手
- 学习伴侣
- 需要记忆历史的任何应用

### 6️⃣ **CustomerServiceChatMemoryStore.java** - 客服系统专用存储

**功能说明**:
- **双层记忆架构**: 用户档案（静态） + 会话历史（动态）
- 支持多个独立会话，每个会话有独立的聊天记录
- 会话开始时自动加载用户档案

**架构设计**:
```
┌─────────────────────────────────────┐
│  用户档案层 (静态信息)              │
│  - 姓名、年龄、职业、会员等级...   │
│  - 所有会话共享                     │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  会话层 (动态历史)                  │
│  - Session 1: 订单咨询              │
│  - Session 2: 会员咨询              │
│  - Session 3: 技术支持              │
│  - ... (相互隔离)                   │
└─────────────────────────────────────┘
```

**核心方法**:
- `initSession(sessionId)`: 初始化新会话（包含用户档案）
- `getAllSessionIds()`: 获取所有活跃会话 ID
- `clearAllSessions()`: 清除所有会话数据

**特点**:
- 用户档案作为系统消息在每个会话开始时注入
- 不同会话之间上下文完全隔离
- 支持动态扩展存储后端（数据库、Redis 等）

**适用场景**:
- 在线客服系统
- 多渠道客户支持
- 多会话管理系统

### 7️⃣ **CustomerServiceExample.java** - 客服系统完整示例

**功能说明**:
- 演示完整的客服系统场景
- 同时使用用户档案和多会话管理
- 展示上下文隔离效果

**场景设定**:
- **会话 1** (`order-session-001`): 讨论订单发货进度
- **会话 2** (`vip-session-002`): 咨询网站会员机制

**核心流程**:
```java
// 1. 创建客服系统存储（加载用户档案）
CustomerServiceChatMemoryStore customerStore = 
    new CustomerServiceChatMemoryStore("./user-profile.txt");

// 2. 为每个会话创建独立的聊天记忆
ChatMemory session1Memory = MessageWindowChatMemory.builder()
    .id("order-session-001")
    .chatMemoryStore(customerStore)
    .build();

ChatMemory session2Memory = MessageWindowChatMemory.builder()
    .id("vip-session-002")
    .chatMemoryStore(customerStore)
    .build();

// 3. 初始化会话（加载用户档案到每个会话）
customerStore.initSession(session1Id);
customerStore.initSession(session2Id);

// 4. 创建 AI 服务（根据会话 ID 选择对应的记忆）
assistant = AiServices.builder(...)
    .chatMemoryProvider(id -> id.equals(session1Id) ? session1Memory : session2Memory)
    .build();
```

**测试结果**:
- ✅ 会话 1 记得讨论的是订单 ORDER-2024-001
- ✅ 会话 2 记得讨论的是会员制度
- ✅ 两个会话互不干扰，上下文完全隔离
- ✅ 每个会话都知道用户的档案信息

**适用场景**:
- 电商平台客服
- SaaS 产品支持
- 多渠道客户关怀

### 方案 B：基于 Redis 的存储

**设计思路**:
```java
public class RedisChatMemoryStore implements ChatMemoryStore {
    
    private final Jedis jedis;
    private final String keyPrefix;
    
    @Override
    public List<ChatMessage> getMessages(Object memoryId) {
        String key = keyPrefix + ":" + memoryId;
        Set<String> messages = jedis.zrange(key, 0, -1);
        // 反序列化 JSON 到 ChatMessage 对象
    }
    
    @Override
    public void updateMessages(Object memoryId, List<ChatMessage> messages) {
        String key = keyPrefix + ":" + memoryId;
        Pipeline pipeline = jedis.pipelined();
        pipeline.del(key);
        
        for (int i = 0; i < messages.size(); i++) {
            String json = ChatMessageSerializer.messageToJson(messages.get(i));
            pipeline.zadd(key, i, json);
        }
        pipeline.exec();
    }
}
```

**数据结构**:
```
Key: langchain4j:chat_memory:{memoryId}
Type: ZSET (Sorted Set)
Value: JSON 格式的 ChatMessage
Score: 消息序号（用于排序）
```

**优点**:
- 高性能（内存操作）
- 支持过期策略（TTL）
- 天然支持分布式
- 丰富的数据结构

**缺点**:
- 数据易失（需配置 RDB/AOF）
- 成本相对较高
- 查询能力有限

**适用场景**:
- 高并发场景
- 实时对话系统
- 临时会话（可设置过期时间）

### 方案 C：基于 MongoDB 的存储

**设计思路**:
```java
public class MongoChatMemoryStore implements ChatMemoryStore {
    
    private final MongoCollection<Document> collection;
    
    @Override
    public List<ChatMessage> getMessages(Object memoryId) {
        FindIterable<Document> documents = collection.find(
            eq("memoryId", memoryId)
        ).sort(Sorts.ascending("seqNo"));
        
        List<ChatMessage> messages = new ArrayList<>();
        for (Document doc : documents) {
            messages.add(ChatMessageDeserializer.messageFromJson(doc.getString("content")));
        }
        return messages;
    }
    
    @Override
    public void updateMessages(Object memoryId, List<ChatMessage> messages) {
        // 使用 bulkWrite 批量操作
        List<WriteModel<Document>> writes = new ArrayList<>();
        for (int i = 0; i < messages.size(); i++) {
            Document filter = new Document("memoryId", memoryId)
                .append("seqNo", i);
            Document update = new Document("$set", 
                new Document("content", ChatMessageSerializer.messageToJson(messages.get(i))));
            writes.add(new ReplaceOneModel<>(filter, update, new ReplaceOptions().upsert(true)));
        }
        collection.bulkWrite(writes);
    }
}
```

**文档结构**:
```json
{
  "_id": ObjectId("..."),
  "memoryId": "user-001",
  "seqNo": 0,
  "type": "USER",
  "content": "{\"type\":\"user\",\"content\":\"你好\"}",
  "timestamp": ISODate("2024-01-01T12:00:00Z")
}
```

**优点**:
- Schema-less，灵活
- 水平扩展能力强
- 支持丰富查询
- 原生 JSON 支持

**缺点**:
- 事务支持有限（单文档）
- 占用空间较大
- 学习曲线

**适用场景**:
- 大数据量
- 需要灵活 schema
- 云原生应用

### 方案 D：组合模式 - 多层存储架构

**设计理念**:
将用户档案存储和会话历史存储分离，使用组合模式灵活搭配不同的存储后端。

**架构设计**:
```java
public class CompositeChatMemoryStore implements ChatMemoryStore {
    
    // 用户档案存储（可以是文件、数据库、Redis）
    private final UserProfileStorage userProfileStorage;
    
    // 会话历史存储（可以是文件、数据库、Redis、MongoDB）
    private final ChatHistoryStorage chatHistoryStorage;
    
    public CompositeChatMemoryStore(
        UserProfileStorage userProfileStorage,
        ChatHistoryStorage chatHistoryStorage) {
        this.userProfileStorage = userProfileStorage;
        this.chatHistoryStorage = chatHistoryStorage;
    }
    
    @Override
    public List<ChatMessage> getMessages(Object memoryId) {
        return chatHistoryStorage.getMessages(memoryId);
    }
    
    @Override
    public void updateMessages(Object memoryId, List<ChatMessage> messages) {
        chatHistoryStorage.updateMessages(memoryId, messages);
    }
}
```

**存储策略接口**:
```java
// 用户档案存储接口
public interface UserProfileStorage {
    SystemMessage loadProfile(String userId);
    void saveProfile(String userId, SystemMessage profile);
}

// 会话历史存储接口
public interface ChatHistoryStorage {
    List<ChatMessage> getMessages(Object memoryId);
    void updateMessages(Object memoryId, List<ChatMessage> messages);
    void deleteMessages(Object memoryId);
}
```

**组合示例**:
```java
// 场景 1: 文件档案 + Redis 会话（适合小型电商）
UserProfileStorage fileProfile = new FileUserProfileStorage("./profiles");
ChatHistoryStorage redisHistory = new RedisChatHistoryStorage(redisClient);
ChatMemoryStore store1 = new CompositeChatMemoryStore(fileProfile, redisHistory);

// 场景 2: 数据库档案 + MongoDB 会话（适合大型企业）
UserProfileStorage dbProfile = new DatabaseUserProfileStorage(dataSource);
ChatHistoryStorage mongoHistory = new MongoChatHistoryStorage(mongoClient);
ChatMemoryStore store2 = new CompositeChatMemoryStore(dbProfile, mongoHistory);

// 场景 3: Redis 档案 + 数据库会话（适合高并发客服）
UserProfileStorage redisProfile = new RedisUserProfileStorage(redisClient);
ChatHistoryStorage dbHistory = new DatabaseChatHistoryStorage(dataSource);
ChatMemoryStore store3 = new CompositeChatMemoryStore(redisProfile, dbHistory);
```

**优点**:
- 高度灵活，可按需组合
- 各层独立优化
- 易于扩展和维护
- 符合单一职责原则

**缺点**:
- 初始设计复杂度较高
- 需要定义清晰的接口

**适用场景**:
- 复杂业务场景
- 需要精细化控制
- 长期演进的系统

## 📊 方案对比总结

| 存储方案 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **内存** | 最快、简单 | 重启丢失 | 临时对话、原型开发 |
| **文件** | 简单、无需额外服务 | 性能低、不支持并发 | 本地应用、小规模 |
| **数据库** | 持久化、支持复杂查询 | 需要 DB 服务、IO 较慢 | 企业应用、需要分析 |
| **Redis** | 高性能、支持过期 | 数据易失、成本较高 | 高并发、实时对话 |
| **MongoDB** | 灵活、易扩展 | 事务有限、占用大 | 大数据、云原生 |
| **组合模式** | 高度灵活、分层优化 | 设计复杂 | 复杂业务、长期演进 |

## 🎯 选择建议

### 1. 快速原型/个人项目
- **推荐**: 内存 or 文件
- **理由**: 简单快速，零成本

### 2. 小型电商/博客
- **推荐**: 文件（用户档案）+ Redis（会话）
- **理由**: 成本低，性能好

### 3. 中型企业应用
- **推荐**: 数据库（用户档案）+ MongoDB（会话）
- **理由**: 平衡性能和复杂度

### 4. 大型电商平台
- **推荐**: Redis（用户档案缓存）+ MongoDB（会话）+ 数据库（归档）
- **理由**: 高可用、高并发、可扩展

### 5. 客服 SaaS 平台
- **推荐**: 组合模式（多租户隔离）
- **理由**: 灵活适配不同客户需求

## 💡 最佳实践

### 1. 分层设计
- 静态信息（用户档案）和动态信息（会话历史）分离
- 便于针对性优化

### 2. 缓存策略
- 热点数据（最近会话）使用 Redis
- 冷数据定期归档到数据库/文件系统

### 3. 过期清理
- 为会话设置合理的 TTL
- 定期清理无效数据，节省存储空间

### 4. 监控告警
- 监控存储空间使用率
- 设置阈值告警，及时扩容

### 5. 备份恢复
- 定期备份重要数据
- 建立灾难恢复预案
