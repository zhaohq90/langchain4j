# Skills

在 LangChain4j 的整体能力版图中，**Skills** 可以理解为一种比单个 Tool 更高层、可复用程度更高的能力封装方式。它适合把一组可协同完成特定任务的能力组织成更稳定的单元，从而供 Agent 或上层流程重复使用。

## 为什么需要 Skills

如果 Tool 更像一个单点函数能力，那么 Skill 往往更像一个可命名、可复用、可组合的任务能力模块。随着系统复杂度增加，直接把大量零散工具暴露给模型会带来管理困难，而 Skills 提供了一种更结构化的能力组织方式。

| 层级 | 典型理解 |
|---|---|
| Tool | 单一函数或单一步骤能力 |
| Skill | 面向某类任务的可复用能力组合 |
| Agent | 面向目标的动态决策与执行协调者 |

## Skills 的工程价值

在工程实践中，Skills 的重要价值通常体现在两个方面。第一，它有助于能力沉淀，把重复出现的任务模式封装起来；第二，它有助于复杂系统的分层设计，使 Agent 不必直接面对过多低层细节，而是可以围绕更高层的能力单元进行编排。

例如，你可以把“检索知识并生成带引用回答”视为一个 Skill，把“抓取网页并提取结构化信息”视为另一个 Skill。这样做之后，上层 Agent 面对的就不再是一堆零散函数，而是一组更接近业务动作的可复用能力块。

## Skills 与 Agent、Subagent 的关系

当系统进入多 Agent 或 Subagent 架构后，Skills 的意义会更加明确。很多情况下，一个 Subagent 实际上就是围绕某个 Skill 或一组紧密相关 Skills 设计出来的。也就是说，Skills 往往是形成 Subagent 能力边界的重要基础。

因此，如果你后续要学习多 Agent 与 subagent，那么理解 Skills 作为“能力模块化单元”的意义会非常有帮助。

## 学习建议

对于初学者，Skills 不一定是最早需要掌握的主题。更合理的顺序通常是先学 ChatModel、AI Services、Tools、Chat Memory 和 RAG，然后再学习 Agents、MCP 与 Skills。这样在理解 Skills 时，你会更清楚它到底是在封装什么、服务于谁，以及在系统中处于什么层级。
