# 模型参数

在 LangChain4j 中，你可以通过多种方式控制 LLM 的行为。除了在系统消息中设定模型的角色和指令外，还可以通过调整各种**模型参数**来微调其输出。这些参数通常在构建模型实例时进行配置，或者在调用 `chat` 方法时作为选项传入。

## 核心模型参数

虽然不同的 LLM 提供商会暴露各自特有的参数，但 LangChain4j 抽象层也提供了一些通用的、跨模型供应商的核心参数，它们对模型的行为有显著影响。

| 参数 | 说明 | 典型值范围 | 影响 |
|---|---|---|---|
| `temperature` | 控制模型输出的随机性。值越高，输出越随机和富有创意；值越低，输出越确定和集中。 | `0.0` (确定性) 到 `2.0` (高随机性) | 创意性、多样性 |
| `topP` | 控制模型在生成下一个 token 时考虑的 token 集合。模型会选择累积概率达到 `topP` 的最小 token 集合。 | `0.0` 到 `1.0` | 文本多样性，与 `temperature` 类似但机制不同 |
| `maxTokens` | 限制模型生成响应的最大 token 数量。 | 正整数 | 响应长度 |
| `presencePenalty` | 对模型生成新 token 的惩罚。值越高，模型越倾向于不重复已经出现过的主题。 | `-2.0` 到 `2.0` | 主题重复度 |
| `frequencyPenalty` | 对模型重复 token 的惩罚。值越高，模型越倾向于不重复使用相同的词语。 | `-2.0` 到 `2.0` | 词语重复度 |
| `logRequests` | 是否记录发送给 LLM 的请求。 | `true` / `false` | 调试、审计 |
| `logResponses` | 是否记录从 LLM 接收到的响应。 | `true` / `false` | 调试、审计 |

## 如何配置模型参数

这些参数通常在构建 `ChatModel` 实例时通过 `builder` 方法进行配置。例如，在使用 `OpenAiChatModel` 时：

```java
OpenAiChatModel model = OpenAiChatModel.builder()
    .apiKey(System.getenv("OPENAI_API_KEY"))
    .modelName("gpt-4o-mini")
    .temperature(0.7) // 设置温度，增加创意性
    .topP(0.9)        // 设置 topP
    .maxTokens(500)   // 限制最大输出 token 数量
    .logRequests(true) // 记录请求日志
    .logResponses(true) // 记录响应日志
    .build();
```

对于某些参数，你也可以在调用 `chat` 方法时动态传入，以覆盖模型实例的默认配置。这在需要针对特定请求调整模型行为时非常有用。

## 为什么模型参数很重要

模型参数是微调 LLM 行为的关键。通过合理调整这些参数，你可以让模型在不同场景下表现出不同的“个性”：

*   **创意性任务**：例如内容生成、故事创作，可以适当提高 `temperature` 和 `topP`，让模型输出更具多样性。
*   **事实性任务**：例如知识问答、数据提取，通常会降低 `temperature` 和 `topP`，以获得更确定和准确的回答。
*   **避免重复**：通过调整 `presencePenalty` 和 `frequencyPenalty`，可以减少模型在长文本生成中出现重复内容的问题。
*   **成本控制**：`maxTokens` 参数直接影响模型生成响应的长度，从而间接影响 API 调用成本。

理解并掌握这些参数的用法，是构建高质量 LLM 应用的重要一环。

## 供应商特定参数

除了 LangChain4j 提供的通用参数外，许多模型供应商还会提供其特有的参数。例如，OpenAI 可能有 `stop` 序列、`logit_bias` 等。LangChain4j 的集成模块通常会暴露这些供应商特定的参数，允许你进行更细粒度的控制。

在使用特定模型时，建议查阅其对应的 LangChain4j 集成文档，了解所有可用的配置选项。

## 学习建议

在学习模型参数时，建议通过实验来感受不同参数对模型输出的影响。例如，尝试用不同的 `temperature` 值让模型生成一段文本，对比其创意性和确定性的变化。这将帮助你建立直观的理解，并在实际项目中做出更合理的选择。
