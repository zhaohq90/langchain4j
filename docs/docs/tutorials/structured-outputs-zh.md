# 结构化输出

在很多业务场景中，模型输出如果只是自由文本，其实并不够用。因为业务系统往往需要的是**可解析、可验证、可落库、可继续处理的数据结构**。LangChain4j 中的 **Structured Outputs**，就是为了解决这一问题而设计的。

## 为什么结构化输出重要

如果你要做的是信息抽取、分类、表单填充、流程判断、工单生成、数据清洗、规则引擎对接或 API 请求组装，那么纯文本回答通常无法直接进入下游系统。你真正需要的是对象、字段、枚举、列表或 JSON 结构。

结构化输出的意义就在于，让模型回答从“面向人阅读”转向“同时面向系统消费”。

| 场景 | 为什么需要结构化输出 |
|---|---|
| 信息抽取 | 需要把姓名、时间、地点、金额等字段拆出来 |
| 分类与路由 | 需要明确分类标签，而不是模糊自然语言 |
| 数据入库 | 需要固定字段格式 |
| 工作流编排 | 下游系统需要确定的参数和状态 |

## LangChain4j 中的定位

在 LangChain4j 的整体能力体系中，结构化输出通常与 AI Services 配合使用最自然。开发者可以把模型输出映射为 Java 对象，从而让 AI 能力更容易融入传统 Java 服务体系。

这也是 LangChain4j 很适合企业应用的原因之一。因为企业系统通常并不只需要“看起来聪明的对话”，而是需要“能够进入业务流程的数据”。

## 学习重点

学习结构化输出时，建议重点关注三件事。第一，如何把业务需求拆成稳定字段；第二，如何让模型尽量输出符合预期的结构；第三，如何在工程上对结果做校验与兜底。

你可以把这一能力理解为“让模型成为一个柔性的上游解析器”，但最终进入系统的数据仍应具备明确的验证机制。

## 与其他章节的关系

结构化输出与多个主题都有天然联系。它可以建立在基础聊天之上，也可以与 AI Services、Tools、RAG、Guardrails 结合使用。尤其是在 Agent 系统中，结构化输出常被用来表达计划、动作、参数与阶段结果。

因此，如果你的目标不是做一个简单聊天机器人，而是做可落地的业务系统，那么结构化输出是必须掌握的关键能力之一。
